# LLMプロンプト

各 `.txt` は `src/prompts.go` の `go:embed` によりバイナリへ組み込みます。変更後はCLIの再ビルドが必要です。スキルの指示は含みません。

| ファイル | 用途 | `fmt.Sprintf` の引数（順序固定） |
| --- | --- | --- |
| `generate.txt` | 依頼から提案生成 | `%s`: 依頼文 |
| `issue.txt` | GitHub issueから提案生成 | `%s`: issueのJSON |
| `revise.txt` | `revise` とコメント付き `clarify` の提案全体の再構成 | `%s`: 元の依頼・承認済み決定・全レビュー履歴・現在の未解決項目の共通JSON |
| `clarify.txt` | 新しい確認事項の抽出 | `%s`: 履歴JSON、`%d`: 追加可能件数 |
| `spec.txt` | 承認項目のみの要約 | `%s`: 承認項目のJSON配列 |

## 編集時の注意

- 初回分離では既存プロンプトをそのまま移動しました。`revise` はその後、全体再構成へ変更しています。共通文も、タスク間の違いを維持するため各ファイルに残しています。
- テンプレートは `fmt.Sprintf` 形式です。指示文にリテラルの `%` を追加する場合は `%%` と書きます。引数として渡される依頼やJSON内の `%` はエスケープ不要です。
- 改行や末尾の改行もLLMに渡ります。現在のファイルには末尾改行がありません。
- 出力形式・件数・履歴の検証はGoコード側の責務です。プロンプトだけで制約を強制できるとは扱いません。
- `src/prompts_test.go` は分離前の出力を固定しています。意図的に指示を変更する際は、期待値と関連する動作テストも確認してください。

```sh
go test ./src -run TestExtractedPromptsPreserveOutput -count=1
go test ./src
```

Pi・fxの実エンジンによる再構成例は明示的に有効化して実行します（通常のテストではスキップ）。各エンジンのインストール・認証が必要で、モデルを呼び出します。

```sh
PROP_REVIEW_LIVE_ENGINES=pi,fx go test ./src -run '^TestClarifyLiveEngines$' -v -count=1
```

表示される生成結果について、JSON制約の維持、標準出力への変更、保存先設定の不要化、全項目の未承認を人間が確認してください。テストの成功は意味的な正しさの自動承認ではありません。
