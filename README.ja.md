# prop-review

[English README](README.md)

提案を項目ごとにレビューするローカルCLIです。zintentのIntent承認ゲートとは独立しています。ソースコードは `src/` にあります。

## インストール（どのリポジトリからでも利用可能）

このリポジトリのルートで実行します。`~/.local/bin` を `PATH` に追加してください。

```sh
mkdir -p "$HOME/.local/bin" "$HOME/.pi/agent/skills"
go build -o "$HOME/.local/bin/prop-review" ./src
for skill in prop-review prop-review-ingest; do
  if [ ! -e "$HOME/.pi/agent/skills/$skill" ] && [ ! -L "$HOME/.pi/agent/skills/$skill" ]; then
    ln -s "$PWD/skills/$skill" "$HOME/.pi/agent/skills/$skill"
  fi
done
```

共有の `~/.agents/skills` ディレクトリに対応したPi以外のエージェントでも使う場合は、そちらにもスキルへのリンクを作成します。

```sh
mkdir -p "$HOME/.agents/skills"
for skill in prop-review prop-review-ingest; do
  if [ ! -e "$HOME/.agents/skills/$skill" ] && [ ! -L "$HOME/.agents/skills/$skill" ]; then
    ln -s "$PWD/skills/$skill" "$HOME/.agents/skills/$skill"
  fi
done
```

既存のリンク先は上書きしません。必要に応じてリンク先を確認してください。Piを起動済みなら `/reload` を実行します。

## レビュー

```sh
prop-review
```

Gitリポジトリ内のどこからでも実行できます。リポジトリのルートにある未レビューの `prop-review-tmp/review.*/proposal.txt` が1件なら開き、複数なら一覧から選択します。並び順は提案ファイルの更新日時、同時刻ならパスの降順です。一覧の番号を入力するか、`q` で中止します。`prop-review proposal.txt` のようにパスを指定することもできます。以前の提案や結果は上書き・削除しません。`generate` と `revise` は固有のディレクトリを作成し、必要であればリポジトリのローカルなGit `info/exclude` に `/prop-review-tmp/` を追加します。レビューだけならGitの設定は変更しません。

提案ファイルは1項目につき2行で、レビュー欄は空欄です。生成されたファイルでは項目間に空行が入ります。`Approval/Comment:` は固定のファイル形式トークンで、提案文には依頼の言語を使えます。以下は形式の例であり、組み込みの操作ではありません。

```text
現在の設定をエクスポートするコマンドを追加する
Approval/Comment:

保存したレビューの復元方法を文書化する
Approval/Comment:
```

提案で使用できる欄は `Approval/Comment:` のみです。項目の文言を形式上の接頭辞として解釈することはありません。項目は空でない単一行とし、不正なUTF-8、置換文字 `�`、制御文字は使用できません。

承認は `a`、コメント入力は `c`、未確認のままにするにはEnterだけを入力します。`b` で前の項目に戻り、`q` で保存せずに終了します。各選択はEnterで確定し、その改行が次の項目を飛ばさないようにしています。全角のラテン文字キーにも対応しています。依頼文とコメントの入力では、左右キー、Home/End、Backspace（マルチバイト文字を含む）を使えます。コメントは最大1 MiBのUTF-8です。超過時は切り詰めずに入力を拒否します。空のコメントは未確認のままになることを警告し、Enterで確定、Escで戻れます。

結果は既定で提案と同じディレクトリの `proposal.review.txt` に保存され、そのパスが表示されます。既存の結果は上書きしません。別の保存先を使う場合は `prop-review proposal.txt /path/to/result.txt` とします。レビューを中断した場合は保存しません。ファイル形式では `Approved` と `Comment: "..."` で承認とコメントを区別します。コメントは引用・エスケープして保存し、読み込み時に復号します。レビュー結果で認められる値は空欄の `Approval/Comment:`、`Approved`、`Comment: "..."` のみで、ほかの形式は拒否します。

## 放棄した提案の削除

```sh
prop-review delete
```

現在のリポジトリから、未レビューの提案（隣接する `proposal.review.txt` がないもの）と、改訂待ちのレビュー済み提案（コメントがあり、子の改訂がないもの）を一覧表示します。番号を選ぶか `q` で中止します。削除前に提案全文と、存在する場合は**承認済み項目も含む**レビュー結果を表示します。`delete` と入力した場合だけ削除し、それ以外の入力や中断では何も削除しません。別の提案の `parent.txt` から参照されているレビューは削除対象になりません。候補ディレクトリにリンクや想定外のファイルがある場合も拒否します。選択した `review.*` ディレクトリと、その提案、隣接するレビュー結果、`parent.txt` などのメタデータを恒久的に削除します。他の議論は削除しません。

## 提案の生成と改訂

fxを使うには `fx` CLIのインストールと認証が必要です。Piを使うにはNode.jsとグローバルnpmパッケージ `@earendil-works/pi-coding-agent` をインストールし、認証情報とモデルを設定します。Piによる生成は `pi` CLIではなく**SDK**を使用します。ほかに `claude`、`codex`、`agy`（Antigravity CLI）、`opencode` CLIも利用できます。それぞれインストールと認証が必要です。選択したエンジンはリポジトリ間で共有するユーザー単位の設定で、初期値はPiです。libfxやモデルAPIへの直接接続は使用しません。

```sh
prop-review engine       # 現在のエンジンを表示（初期値はPi。設定は変更しない）
prop-review --engine pi  # fx、claude、codex、agy、opencodeも指定可能
prop-review generate     # 依頼を入力し、提案を生成してレビュー
prop-review issue        # 未解決のGitHub issueを選び、提案を生成してレビュー
prop-review clarify      # 元の依頼またはissueタイトルを選び、追加確認事項をレビュー
prop-review spec         # 全レビュー系列の承認済み項目を1つの仕様に保存
prop-review revise       # 改訂待ちの提案を選び、新しいproposal.txtを保存
prop-review revise prop-review-tmp/review.123/proposal.txt  # 対象を直接指定
prop-review              # 改訂後の提案をレビュー
prop-review --engine fx  # fxへ切り替え
```

エンジンの設定はOSのユーザー設定ディレクトリ（`os.UserConfigDir()`）内の `prop-review/engine` に保存されます。`generate` と `revise` はリポジトリ内の端末で実行します。

新しい `generate` のルートには入力した依頼文を、新しい `issue` のルートにはissueタイトルを `request.txt` として保存します。`request.txt` がないルートの依頼文は復元できず、`clarify` には使えません。選択一覧ではinvalidと表示します。これはレビュー結果の形式とは無関係です。このローカルなレビュー情報には非公開の依頼文が含まれることがあります。`prop-review-tmp/` は既定でGitの追跡対象から除外されます。`issue` には認証済みの `gh` CLIと、`gh` が認識できるGitHubリポジトリが必要です。開いているissueを最初の30件（`gh issue list` の既定値）まで一覧表示し、端末で番号を選びます（`q` で中止）。選んだissueのタイトル、本文、番号、URLをエンジンに渡します。一覧外のissueは選べません。JSONで256 KiBを超えるissueデータは拒否します。issue本文は信頼できない入力として扱い、CLIはissueを変更しません。生成成功後は `generate` と同様に新しい提案のレビューを開始します。

エンジンにはリポジトリを参照して提案を作るよう指示し、実装は指示しません。最初の依頼文は最大256 KiBのUTF-8で、前後の空白を取り除いてから渡します。新規提案には依頼文の言語、改訂には元の提案項目の言語を使うよう指示します。コメントの言語が異なる場合も同様ですが、言語はプログラムでは検証しません。Piは拡張・スキル・プロンプトテンプレートを無効化したメモリ内セッションと読取専用ツールを使用します。Claudeはセッションを保存せず、制限モードでRead/Glob/Grepだけを使用します。Codexは読取専用サンドボックスと一時セッションを使用します。Antigravity（`agy`）は非対話のplanモード、端末サンドボックス、スラッシュコマンド無効化で実行しますが、自身のローカルなセッション情報は保存する可能性があります。単独の `gemini` CLIは使用しません。以前 `gemini` を選んでいた場合は `prop-review --engine agy` で変更してください。OpenCodeはread/glob/grepだけを許可する専用エージェントを使って単独実行します。プロンプトはコマンドライン引数として渡し、100,000バイトを超える場合は拒否します。外部CLIのローカル設定、フック、プラグインはツールの権限制限とは別の副作用を起こす可能性があるため、信頼できるインストールを使用してください。外部プロセス `fx ask --no-save` にはファイルを変更しないよう指示しますが、そのツール権限をCLI側では強制できません。エンジンの実行中は標準エラー出力に `⠋ Generating proposals with <engine>...` のスピナーを表示します。100秒を超えると、提案を保存せずにタイムアウトします。

`prop-review spec` は選択なしで全レビュー系列の履歴と結果を検証し、承認済み項目だけを `prop-review-tmp/spec.md` にまとめて保存します。追加確認事項が見つかった場合も保存し、`prop-review clarify` を推奨します。旧レビューに `request.txt` がなく確認できない場合は警告します。既存ファイルは上書きしません。実装や他の承認処理は開始しません。

`prop-review clarify` はルートの依頼文またはissueタイトルを一覧表示し、**ユーザーがルートを選択**します。他のルートと混ぜず、同じ系統の `parent.txt` による履歴と各レビュー結果を検証します。分岐が曖昧な場合、結果の欠落、リンクの不正、ルートの依頼文の欠落がある場合は、エンジンを呼び出す前に失敗します。選択したエンジンには、ルートの依頼文またはタイトルと、その系統の承認済み・未確認・コメント付きのレビュー履歴を渡します。未確認の項目は引き継ぎ、承認事項から生じる新しい質問だけをエンジンに求めます。承認済み項目の再承認は求めません。エンジンが `[]` を返し、未確認項目もなければ、追加の質問がないと報告して何も保存しません。それ以外の場合は、固有の `review.*` ディレクトリに新しい提案を保存します。`followup.txt` と `parent.txt` で元の履歴につなぎ、レビューを開始します。元のファイルは上書きしません。現在のレビューにコメントがあれば、まず `revise` を行うよう推奨します。未確認項目が残れば、新しい提案でもう一度レビューするよう推奨します。これらのメッセージは生成を中断しません。`revise` は引き続きコメント付き項目だけを改訂し、`clarify` が承認済み作業を実装することはありません。

応答は1～10件の空でない単一行の提案を含むJSON配列として検証し、レビュー欄が空の `proposal.txt` に変換します（`clarify` のみ `[]` も受け付けます）。引数のない `revise` は、コメントがあり子の改訂がないレビュー済み提案が1件ならそれを選び、複数なら一覧から選ばせます（提案の更新日時、同時刻ならパスの降順）。同じリポジトリ内の `prop-review-tmp/review.*/proposal.txt` を相対パスまたは絶対パスで指定すれば、そのレビュー済み提案を直接改訂します。隣接する結果がない場合や内容が一致しない場合は、別の提案へ切り替えずに失敗します。改訂ではコメント付き項目だけを置き換え、未確認項目は引き継ぎます。承認済み項目は過去の提案と結果に残します。改訂された提案には、直前の `review.*` ディレクトリ名を含む `parent.txt` を置いて履歴をつなぎます。`prop-review-ingest` スキルはこれらのリンクをたどり、以前の承認と最新の結果を合わせて報告します。リンクのない既存の改訂は確実には結合できません。改訂後のレビューは自動開始しません。未確認項目がある場合、`revise` は改訂後の提案でもう一度レビューするよう勧めます。未確認項目だけではコメントがないため、`revise` では改訂できません。生成失敗、不正な出力、入力の中止ではレビューを開始せず、以前のファイルも上書きしません。生成に成功してもレビューを中止した場合は、未レビューの新しい提案が残ります。結果を既定の `proposal.review.txt` 以外に保存した場合、その結果を `revise` に使うことはできません。

完了したレビュー結果をチャットに取り込み、コメントへの回答を含むエージェントの反応を得るには `prop-review-ingest` スキルを使用します。`prop-review` スキルが扱うのは提案生成とレビューへの引き渡しであり、結果の取り込みではありません。承認はその項目だけに適用され、実装は自動で始まりません。
